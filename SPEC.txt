==================================================

Build a complete, production-ready Discord bot called SkyPvP Utils, specifically designed for PikaNetwork SkyPvP.

The bot should provide:

- Player statistics and profiles.
- Player tracking and stat updates.
- Leaderboards and fight information.
- Public auction notifications.
- Personal auction alerts.
- SkyPvP event notifications.
- East and West KOTH monitoring.
- Stronghold notifications.

==================================================

Use the official PikaNetwork Stats API wherever applicable.

API BASE:
https://stats.pika-network.net/api

DOCUMENTATION:
https://stats.pika-network.net/docs

Use documented endpoints for supported information such as:

- Player profiles.
- SkyPvP statistics.
- Player history.
- Leaderboards.
- Fight information.
- Match information.
- Teams where supported.
- Event information where supported.
- Other documented SkyPvP information.

The API supports API-key authentication through the X-Api-Key header.

Read the API documentation before implementing endpoint integrations.

Implement a centralized PikaNetwork API client.

Requirements:

- API key loaded from environment variables.
- X-Api-Key authentication.
- Request timeout handling.
- Response validation.
- Redis caching.
- Rate-limit handling.
- Retry logic with exponential backoff.
- Respect Retry-After headers.
- Respect rate-limit response headers.
- Request deduplication where practical.
- Centralized API error handling.
- Structured API logs without credentials.
- Graceful handling of downtime.

The documented rate limit is 120 requests per minute per key.

Design the system to normally remain below approximately 60–80 requests per minute, leaving capacity for unexpected requests and user commands.

Do not create multiple API keys to bypass the rate limit.

Use configurable cache durations for different data types.

Avoid fetching identical information repeatedly when it is already cached.
